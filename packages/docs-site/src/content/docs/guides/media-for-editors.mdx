---
title: Images and media for editors
description: Upload images, write alt text, choose the right size and crop, and replace or remove files safely in Typeroll's media library and editor.
---

The media library holds a site's images, videos, PDFs and other files. Pages
use them through blocks such as Image, Hero, Gallery, Card, Video and the
background of a section. When a site is published,
Typeroll creates smaller AVIF and WebP versions of each image, so visitors on
phones download less. This guide covers the everyday work.

## Upload

Open **Media** for the site and drag files onto the page, or choose them with
the upload button. You can also pick or upload a file directly from a field in
the [editor](../the-editor/): an image field offers images, a video field
(a hero or background video, the Video block) offers videos, and a file field
offers every kind.

- **Types:** JPEG, PNG, WebP, AVIF, GIF, SVG, ICO, BMP, TIFF, HEIC, JPEG XL,
  PDF, and MP4 or WebM video. See
  [file names and types](../../tools/media/#file-names-and-types).
- **Size:** up to 25 MB per file. Compress a long video first.

## Publish a PDF and share its link

Available from **Core 0.3.44** (MCP **0.45.147**). Cloud needs the matching
platform release; self-hosted installations need to update Core.

1. Upload the PDF and wait for upload verification to finish.
2. Open its details and choose **Publish PDF**. This makes the file public;
   anyone with the resulting link can read it without signing in.
3. After Typeroll verifies the public file, choose **Copy public URL**.
   Use that exact address in email, printed material or links.

This copies the PDF to your organization's public R2 storage. It does **not**
build the website, start image preparation, or need GitHub/a build engine.
An organization media domain must be connected in **Publishing → Domains**,
with private and public R2 storage ready. Cloud and self-hosted installations
use the same organization connection. The file limit is 25 MB.

Uploading alone keeps the original **Private**. **Open private preview** is
for signed-in site members; its `/api/sites/…/content` address is not a sharing
link. The image-preparation notice concerns image variants, not PDFs.

Public addresses use the configured media domain, an anonymous site namespace,
and a content-based filename. Renaming the file's display name or publishing
the website again does not change an individually published PDF's link.
Uploading a new version creates a new file and address; existing links continue
to show the old file until it is deleted. Keep this in mind for printed links.

If verification fails, the copy may already exist publicly, but Typeroll does
not offer an unverified sharing link. Check the media domain and retry
**Publish PDF** on the same item; no re-upload or website build is needed.
Deleting the file also removes its public copies and requests cache removal;
any incomplete removal is reported for retry.

Agents use [`publish_media_file`](../../tools/media/) after uploading and
finalizing, with the owner's authorization to make the PDF public.

## Find a file

The library and the picker show a thumbnail of every file: the image, a frame
of a video (which plays without sound while you point at it), and an icon with
the type for PDFs, audio and other files. Logos and other graphics show whole.
Choose **Images**, **Videos**, **PDFs**, **Audio** or **Other files** to see one
kind, and search by file name or description. Open a file to see it large: a
video plays with its controls, and a PDF opens in a new tab.

- **SVG:** stored only after it has been cleaned of scripts.
- **Before publishing setup:** uploads work before GitHub and Cloudflare are
  connected, but a migration should connect media storage first; see
  [Connect your accounts](../customer-publishing/#storage-before-importing).

## Choose the right size

Typeroll never enlarges an image. Upload enough pixels for the largest place
the image is shown:

| Use                             | Recommended size                        |
| ------------------------------- | --------------------------------------- |
| Full-width hero                 | 1920 × 1080 px or 1600 × 900 px         |
| Share image for social networks | 1200 × 630 px PNG or JPEG               |
| Card thumbnail                  | 800 × 600 px                            |
| Logo                            | SVG, or PNG at twice the displayed size |
| Favicon                         | 32 × 32 px PNG or ICO                   |

Larger files are fine: visitors receive a version that fits their screen.

## Write alt text

Alt text describes an image for people who cannot see it and for search
engines.

- Fill in **Alt text** on the Image block (and the matching field on other
  image blocks) for every image that carries meaning. Describe what the image
  shows in its context, in one sentence, without "Image of".
- Leave it empty for purely decorative images, so screen readers skip them.
- The media library's own **Alt text** field (open a file to edit it) stores a
  description with the file. AI agents and imports reuse it; check it when you
  place the image.

An AI agent can propose alt text with the context of where an image is used
(`suggest_alt_text_context`); review its suggestions before saving.

## Control the crop

Images that fill a fixed area, such as a hero background, a section background
or a card, are cropped to fit. Set the **Image focal horizontal position** and
**Image focal vertical position** (0–100 %) on the Image, Hero, Container and
Post card blocks to keep the subject in view. Check the result on a phone and a
desktop; both positions can differ per screen size.

## Rename, replace and remove

- **Rename** a file or change its title and caption in its details panel. The
  extension must match the file type.
- **Replace** an image on a page by picking another file in the block. The old
  file stays in the library.
- **Delete** a file only when no page uses it: deleting removes it from storage,
  and pages that still show it break. An AI agent can check where a file is used
  with `search_pages` before you delete it.

## Share images

The image social networks show for a page comes from the page's **Meta** panel,
then the site's default share image. SVG, AVIF and TIFF share images are
published as a PNG copy, but a 1200 × 630 PNG or JPEG gives the best result.
See [SEO for your site](../seo/).

## Check it

- Preview the page on a phone and a desktop: every image appears, the subject
  is in view and nothing is blurry.
- Run the [launch readiness report](../launch-checklist/#share-image) to check
  the share images.
- After publishing, open the page and confirm the images load from the site's
  media address.

## Agent batch deletion and protected files

From Core 0.3.45 / MCP 0.45.148, `delete_media_batch` accepts 1–20 explicit
`media_ids` (`DELETE /api/v1/sites/{siteId}/media`, JSON body). It uses the same
write permission, file leases and protection checks as individual deletion,
with bounded concurrency. Inspect every result; HTTP 207 means at least one
item failed, was missing or retained copies. Successful items are still deleted.
Repeating a deleted id reports 404; use `remove_published_media_copies` to retry
its remaining copies.

`objects_protected` means another media record still uses those bytes. It is
not a successful removal of the public file. The `protection` object lists
`referenced_by_media_ids`, `public_urls_retained` and the next step. Keeping the
other record intentionally keeps its shared files public. Delete it only when
the owner wants that file removed too, then retry leftover copies by the deleted
media id. Original objects, prepared variants and public aliases are reported
separately. No automatic cleanup removes a file still owned by another record.

## Files and embedded forms in preview

From Core 0.3.45, stored PDF paths and imported aliases resolve through private
preview media and open in a separate tab, outside the preview sandbox. A preview
does not require publishing the file publicly. If a PDF path cannot be matched
to the media library, the preview explains that it is only available on the
published website and offers that address when known.

External forms may restrict embedding to the published hostname. The preview
shows an expanded explanation before the iframe, with a separate provider
link, even if the provider leaves the iframe blank. A frame load event does
not prove that its form loaded. The preview keeps its origin isolation.
