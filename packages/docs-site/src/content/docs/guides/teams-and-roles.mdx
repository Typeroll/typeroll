People work in a Typeroll **Organization**. Its members share the
Organization's sites and publishing connections, and each member has a role.
Access for other companies and for automated agents uses separate, narrower
mechanisms described below.

## Roles

| Role        | Who has it                              | On the Organization's sites                                                                                              | In the Organization                                                |
| ----------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| **Owner**   | The person who created the Organization | Everything, including publishing, settings and domains                                                                   | Members and owners, publishing connections, organization API keys  |
| **Admin**   | Members given the admin role            | The same as an owner                                                                                                     | Members (not owners), invitations, publishing connections and keys |
| **Builder** | Members given the builder role          | Everything an editor does, plus design: colours, fonts, styles, Site CSS, block types, templates, site field definitions | The [organization collection](../../tools/collection/)             |
| **Editor**  | Members given the editor role (default) | Edit and save content: pages, blocks, partials, templates, menus and media                                               | Nothing administrative                                             |

A **builder** sets up and designs sites: the Design and General sections of
Site settings (colours, fonts, typography, scales, widths, logo and icons), the
Fonts library, styles and the Site CSS, the render version, block types,
templates, settings pages (site field definitions), package imports with the
whole look, and the organization collection. A builder cannot manage members
or invitations, billing, publishing connections, domains, API keys, sharing,
forms and email settings, apps, branches, the site lifecycle, the content
export or a whole-site package export, and does not publish.

An editor cannot publish a site, change Site settings, manage API keys or
sharing, change domains, create or merge branches, configure forms, email or
apps, or download the content export. An owner or admin publishes the work.

Organizations created before roles were enforced treat every member as an
admin until enforcement is turned on for them.

## Manage members

Owners and admins see every member, with their role, under **Account →
Members**. There they change a role or remove someone. The same is available
to agents:

- `list_organization_members` lists each member's id, email, name, role and
  when they joined.
- `update_organization_member_role` changes a role to owner, admin, builder or
  editor.
- `remove_organization_member` removes a member; their access to every site
  of the Organization ends at once.

Only an owner makes someone an owner, or changes or removes an owner. The
last owner can be neither demoted nor removed: make someone else an owner
first. Anyone can leave an Organization, except its last owner.

## Invite people

Each invitation is a link for joining the Organization with a role:
**editor** by default, or **builder** or **admin**. Nobody is invited as an
owner; make a member an owner afterwards. An invitation is single use unless
you allow more, expires after 7 days by default (1–30 days), and can be
limited to one email address.

Owners and admins create invitations under **Account → Members**, or through
the API or an AI agent connected with the Organization's access:

```text
Create an invitation to our Typeroll Organization for anna@example.com as a
builder, valid for 14 days, and give me the link.
```

The agent calls `create_organization_invite` with `role: "builder"`. Send the
link to the person yourself. They open it, sign in or create an account, and
join with that role. People who already joined keep their membership and role
if the invitation is later revoked.

- `list_organization_invites` shows each invitation's state and role: active,
  used, expired or revoked. It never shows the link again.
- `revoke_organization_invite` stops a link immediately.

The API routes are described in
[Organization, access and workflow tools](../../tools/organization/#invite-people-to-the-organization).

## Give another company access to one site

Don't invite a client or a partner into your Organization: membership covers
all of its sites. Share the one site with their Organization instead, from
**Site settings → Access & AI → Manage sharing**, with **read**, **write** or
**admin** permission. See [Agencies and client sites](../agencies/#give-the-client-access).

## Give agents and scripts access

| Access                     | Use it for                                              | Where                                                                                        |
| -------------------------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **Personal AI connection** | Your own AI agent, with exactly your access             | Connect the hosted MCP server and sign in; see [Personal AI connections](../ai-connections/) |
| **Site API key**           | A script or agent for one site                          | **Site settings → Access & AI → External access**                                            |
| **Organization API key**   | An agent that manages many sites or publishing settings | **Account → API keys**, owners and admins only                                               |

API keys are shown once when they are created and are never available through
the API or MCP. Revoke a key from the same page as soon as it is no longer
needed. See [Connect your AI agent](../../getting-started/mcp-server/#choose-credentials).

## Check it

- `list_organization_members` shows only the people and roles you intend.
- `list_organization_invites` lists no active invitation you did not intend.
- `list_organization_api_keys` and each site's `list_api_keys` show only keys
  that are still in use.
- `list_site_shares` on each site shows only the intended Organizations.
