The migration workflow and helper plugin are included in the open-source
Typeroll distribution. Typeroll Cloud also offers migration as an operated,
supported service.

## Overview

The migration workflow imports accessible WordPress content (pages, posts and supported custom post types) into a new Typeroll site, transfers your media directly to your organization’s Cloudflare R2 storage, and generates redirects from old URLs to new slugs.

**What it does:**

- Imports pages and posts as Typeroll pages
- Transfers media (images) through the media API — only images actually used on imported pages
- Maps custom post types to Typeroll content types
- Generates URL redirects
- Leaves everything as drafts for your review before going live

**What it doesn't do:**

- Import your old WordPress theme or CSS (you build a new design in Typeroll)
- Import plugins or plugin-specific data that isn't content
- Touch the source WordPress site in any way

## Before you start

<Aside type="note" title="Own storage is required before importing">
  Starting with Core 0.1.95, imports are locked until your organization’s own R2
  storage is connected and verified. Open the sidebar → **Publishing** → **Media
  storage**. An organization owner or admin completes the setup there. A GitHub
  connection, website domain and build provider are not required to import.
  Ordinary editing and expiring previews remain available before setup.
</Aside>

<Steps>

1. **Build the target site's design**

   The migration imports content into your new design — not the old one. Before starting the migration, set up:
   - Colour palette and fonts (`update_site_settings`)
   - Header partial with navigation
   - Footer partial
   - 1–2 example pages (home, about) — the AI agent uses these as design references

2. **Check that the WP REST API is accessible**

   The migration needs `https://yoursite.com/wp-json/wp/v2/` to be publicly accessible. Test it in your browser — you should see a JSON response.

   If the REST API is disabled or restricted, [install the helper plugin](#helper-plugin) which provides a separate authenticated export endpoint. Your administrator must allow access to that endpoint.

3. **Optional: install the helper plugin**

   The helper plugin gives the AI agent access to custom post types, ACF fields and navigation menus that may not be exposed via the standard REST API.

</Steps>

## Running the migration

Start your AI agent and describe the migration:

```
Migrate my WordPress site at https://acme.se to this Typeroll site.
```

Or with the helper plugin:

```
Migrate the WordPress site at https://acme.se — I've installed the helper plugin
and configured its API key securely in the agent environment.
```

The AI agent will:

1. Call `get_import_readiness` and resolve any storage requirements, then verify the WP REST API connection
2. Build an inventory of all URLs on the site
3. Import pages and posts, transferring images along the way
4. Map any custom post types to content types
5. Generate redirects
6. Show you a coverage report

## Reviewing the migration

After the content is imported, the AI agent shows a coverage report:

```
Migration complete. Here's the coverage:

✅ 24 pages migrated
↪  8 redirects created
⬜ 12 URLs excluded (pagination, feeds, admin)
⚠️  3 URLs unhandled:

  /category/projekt     → needs a redirect or category page
  /tag/stockholm        → tag archive — exclude or redirect to /blog
  /wp-content/uploads/2019/hero.pdf  → file, needs manual handling
```

For each unhandled URL, decide: add a redirect, create a page, or exclude it.

Sites imported with an older Typeroll version may have WordPress entities or
markup left in titles and SEO text. Ask the AI agent to run
`repair_migration_plain_text` as a dry run and show every proposed change. The
repair is restricted to plain-text fields and leaves bodies, slugs, paths, and
URLs alone. Approve the write only after reviewing the returned diffs; records
with existing working copies are skipped rather than overwritten.

## Publishing

All imported pages start as `status: "review"`. When you're satisfied:

```
Publish all the imported pages and deploy.
```

Or review page by page and publish individually.

## Helper plugin

The Typeroll Helper Plugin gives the migration workflow access to:

- Custom post types with `show_in_rest: false`
- ACF fields with image references normalised
- Navigation menus
- Builder JSON (Elementor, Breakdance)
- Complete canonical URL list

**Installing:**

1. Download the `wp-helper-plugin` directory from the Typeroll repository and create a ZIP archive from it.
2. In WordPress: **Plugins → Add New → Upload Plugin**
3. Activate the plugin
4. Go to **Settings → Typeroll Helper** and generate an API key
5. Give the agent the site URL and configure the key through its secure credential mechanism. Keep the key out of shared prompts and documentation.

<Aside type="tip">
  The helper plugin is read-only — it never modifies your WordPress database or
  files.
</Aside>

## Large image libraries

Image transfers use a persistent lookup for each source URL, so repeated imports
reuse verified media. Transfers overlap within limits for memory and each source
host; temporary throttling slows requests down. A failed file does not remove
healthy files already transferred. Keep the WordPress source available until all
required media and references are verified.

With Core 0.1.93 and an updated shared build engine, imported originals also queue
private background image preparation. **Media** shows progress. The Organization's
selected build provider performs encoding; the CMS does not publish draft images.
See [large libraries and first publication](../customer-publishing/#large-libraries-and-first-publication)
for setup, limits and recovery.

## Direct transfers and recovery

With Core 0.1.97, Typeroll sets up a small transfer Worker in your organization’s
connected Cloudflare account. It downloads originals from WordPress directly
into your private R2 bucket and verifies the copied bytes before Typeroll updates
references. File bodies do not pass through the Typeroll Cloud portal or the MCP
server. This is independent of whether GitHub or Cloudflare builds your site.

The **Media storage** card shows transfer setup status. If an existing Cloudflare
connection needs an additional permission, select **Allow media transfers in
Cloudflare**, approve, and return. Your R2 keys remain in place. Advanced token
connections need **Workers Scripts: Edit** as well as the documented R2 access.

Progress is saved per source file. Interrupted copies retain their media identity
and can be retried from Publishing without duplicating completed imports. Typeroll
preserves source URLs until verified copies are ready. Keep the source site
available until the import and reference checks finish. Originals can be up to
25 MB each; responsive variants are prepared separately by the selected build
provider.

The same storage prerequisite applies to self-hosted installations using these
import tools. Configuring the operator’s draft bucket does not satisfy it:
connect the organization’s own storage in Publishing.
