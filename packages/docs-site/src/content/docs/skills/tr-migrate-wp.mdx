**Triggers on:** "migrate from WordPress", a `wp-json` URL, "move my WordPress site"

This skill uses the open-source migration workflow. Typeroll Cloud can also run
and support the same workflow as a managed service.

## What it does

The migration workflow runs in stages:

| Stage               | What happens                                                                                                                                 |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **Discover**        | Verifies the WP REST API is reachable, probes for the helper plugin                                                                          |
| **Inventory**       | Walks the sitemap + REST API to build a complete URL list                                                                                    |
| **Custom types**    | ACF/CPT schemas inferred; each becomes a Typeroll content type whose records are Pages                                                       |
| **Extract content** | Cleaned HTML is kept in HTML mode. Automatic HTML-to-blocks conversion is not applied. Shared terms are referenced and media is copied to R2 |
| **Redirects**       | Old WordPress URLs mapped to new Typeroll slugs                                                                                              |
| **Review**          | Paused for review of URLs, conversion exceptions, shared data and desktop/mobile fidelity                                                    |

All imported pages start with `status: "review"`. You sign off before anything goes live.

## Example prompts

```
Migrate my WordPress site at acme.se to this Typeroll site.
```

```
The source site is at https://old.acme.com/wp-json — migrate it here.

```

## Before you start

The target Typeroll site should already have:

- Colour palette and fonts configured
- Header and footer partials built (at least a basic version)
- Source and target examples for desktop/mobile comparison

The migration imports **content**, not the old design. Presentation comes from shared templates and must be compared with the source before launch.

## The helper plugin

The optional open-source Typeroll Helper Plugin exposes:

- Custom post types regardless of `show_in_rest` setting
- ACF field values with image references normalised
- Navigation menus
- Page builder JSON (Elementor, Breakdance)
- Canonical URL list
- Taxonomy terms, their archive URLs, custom fields and hierarchy

Without the plugin, the migration falls back to the standard `/wp-json/wp/v2/` API, which may miss CPTs and ACF data.

### Installing the helper plugin

1. Download the `wp-helper-plugin` directory from the Typeroll repository and create a ZIP archive from it.
2. Upload to WordPress: **Plugins → Add New → Upload Plugin**
3. Activate it
4. Go to **Settings → Typeroll Helper** and generate an API key
5. Configure the key through your agent’s secure credential mechanism.

<Aside type="tip">
  The helper plugin is read-only — it never modifies your WordPress site.
</Aside>

## Custom post types

Each CPT becomes a Typeroll content type whose records are Pages. The schema is inferred from all imported items’ ACF fields and post meta:

- ACF `image` fields → `type: "image"`
- ACF `text` / `textarea` → `type: "text"` / `type: "textarea"`
- ACF `date_picker` → `type: "date"`
- Unknown fields → `type: "text"` (safe default)

## URL coverage

After migration, the portal's **Migration** tab shows every URL from the source site classified as:

- ✅ **Migrated** — content imported as a page
- ↪ **Redirected** — old URL redirects to a new slug
- ⬜ **Excluded** — pagination, admin, CDN URLs (expected)
- ⚠️ **Unhandled** — needs attention before go-live

You can add redirects directly from the Migration tab for any unhandled URL.

## Media

Images are transferred just-in-time during content extraction. Only images that are actually referenced on imported pages move through Typeroll’s media storage — unused images from the WordPress media library are not transferred.

## Storage prerequisite

With Core 0.1.95 and MCP 0.44.68, the agent first calls `get_import_readiness`.
If storage is not ready, it stops and directs an organization owner or admin to
**Publishing → Media storage**. No content or media is imported into draft
storage as a fallback. Referenced images are copied and verified directly in the
organization’s Cloudflare account.

## Shared data and acceptance

See [shared categories and repeat imports](../../guides/wordpress-migration/#shared-categories-and-repeat-imports)
for the Core 0.2.5 migration behavior. Categories are Pages, and article
fields hold references to them. Never duplicate category names, emojis or
ordering fields per article. Repeated imports preserve saved edits.

Review the home page, an archive and representative articles at desktop and
mobile widths. URL coverage is only one check: record visual, shared-data and
integration evidence before treating the migration as launch-ready.
